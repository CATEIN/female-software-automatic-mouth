# Female SAM on the Commodore 64

`female_sam.prg` speaks typed English on a C64 (or in VICE) in a female or male voice, using SAM's own synthesis method at the original speed.

## Run it

1. Load `female_sam.prg` in VICE or on a real C64 with a **6581 SID**. On an 8580, samples played through the volume register are very quiet.
   - VICE: `x64sc -sidmodel 0 -autostart female_sam.prg`
   - Real C64: `LOAD"FEMALE_SAM",8,1`, then `RUN`.
2. Type a sentence and press RETURN. The screen goes blank while it speaks; that's intended.

Commands (start a line with `#`):

| Command | Effect |
|---|---|
| `#F` / `#M` | female / male voice |
| `#S n` | speed (default 72; higher = slower) |
| `#P n` | pitch (default 64; lower = higher voice) |
| `#O n` / `#T n` | mouth / throat (default 128) |
| `#X` | phonetic input on/off (SAM phonemes, e.g. `/HEH3LOW`) |
| `#?` | help |

Lines are limited to 120 characters.

## How it works

- **Front end:** the reciter (text to phonemes), parser and frame builder are SAM's code from `src/`. All of it is hand-written 6502 (`reciter_asm.s`, `parser_asm.s`, `sammain_asm.s`, `render_asm.s`, `render_fast.s`); only `Init`, `SetInput` and small wrappers remain cc65-compiled C. Everything is built for target `none`. The `c64` target would convert their ASCII character constants to PETSCII; unshifted C64 letters already arrive as ASCII capitals.
- **Female voice:** SAM's own renderer, fed female data (`src/female.c`, `render.c`):
  - formant tables scaled by the Hillenbrand et al. (1995) female/male ratios (8.8 fixed point, capped at 127 units = 3.4 kHz, the Nyquist frequency of SAM's tick rate)
  - pitch periods × 153/256 (F0 × 1.67)
  - on the PC this is `sam.exe -voice female` (the default SAM engine)
- **`samout.s`:** the real-time output loop in 6502 assembly. It follows `render.c`'s loop step for step and writes 4-bit values to `$D418`.
  - Voiced ticks are padded to SAM's 145 cycles on every path. Amplitude × waveform products come from page-aligned tables (`samtables.s`, generated by `tools/gen_c64_tables.py`).
  - IRQs are off and the screen is blanked while speaking.
- **`render_fast.s`:** 6502 versions of `render.c`'s whole-table loops.
- **`main.c`:** the prompt, plus a phrase queue. A sentence's phrases are built first and then played back to back, so building the next phrase doesn't leave a gap mid-sentence.

## Results

| Check | Result |
|---|---|
| Frame tables, 6502 vs native | identical (male + female, 3 sentences) |
| DAC writes, 6502 vs C reference | identical counts. 97–99 % of 4-bit values identical, the rest off by one (rounding of the individual amplitude × waveform terms). |
| Voiced tick | 145 cycles (original 144.8) |
| Unvoiced noise bit | 53.2 cycles on average (original 53.6) |
| Voiced noise bit | 47.2 cycles on average (original 48.3) |
| VICE, 6581 | female ~200–208 Hz and male ~116–122 Hz on the same sentence. Durations match the PC reference. |
| Pause at a comma | 0.21 s (the sentence itself has 0.17 s of silence there) |

Recordings from VICE: `out/c64_female.wav`, `out/c64_male.wav`.

**Delay before speaking:** the whole front end is now 6502 assembly. "Hello, how are you today?" needs ~159 K cycles before the first sound (~0.16 s on a PAL C64). The first straight cc65 compile took ~9 M.

| Part | Cycles | Implementation |
|---|---|---|
| Reciter | ~31 K | `reciter_asm.s`. `reciter_index.s` lists every rule's end and its `(` `)` `=` positions, so SAM's byte-by-byte scans are replaced by lookups with the same results. The input copy stops 16 bytes after the end marker. |
| Phoneme names (`Parser1`) | ~4 K | `parser_asm.s`, with per-character lookup tables in `parser_index.s` |
| Rest of the parser (`Parser2` … `PrepareOutput`) | ~12 K | `sammain_asm.s` |
| Frame building | ~38 K per phrase | `render_asm.s`; blend steps use subtraction instead of an 8-step division |
| Contour / female pitch / rescale | ~10 K per phrase | `render_fast.s` |

**Compared with the original SAM:** it can't be timed directly here, since that would need SoftVoice's 1982 binary. But SAM's C is a transliteration of the original 6502 code, and our first straight assembly ports of each stage (before the lookup tables) together measured ~223 K cycles for this sentence. That is the best available estimate of the original's work. The current front end does it in ~159 K, about 30 % less.

- **Gaps:** phrases play back to back from the queue (`SamPlayTables` patches the player's table addresses, so nothing is copied back). In VICE the pause at a comma is the sentence's own silence (0.17 s), with no added delay.
- **Correctness:** every assembly routine is checked against the native C by `check_c64.py frames` (13 sentences, both voices, changed settings, sing mode). VICE confirms female ~200–207 Hz and male ~116–122 Hz.
- **Generated tables:** `reciter_index.s` and `parser_index.s` come from `tools/gen_rule_index.py` and `tools/gen_parser_index.py`, which read the real tables through `tools/dump_rules.c` / `tools/dump_parser.c` (built with MSVC). Rerun them if SAM's rule or phoneme tables change.

`tools/profile6502.py` profiles any cc65 program by function, by inclusive time and by C source line: `python tools\profile6502.py prog.prg prog.lbl --dbg=prog.dbg`.

## Notes

- `py65` counts `DEC abs` as 3 cycles. The harness corrects it to 6, the real 6502 value.
- Changing `src/` for the C64: cc65 is C89, so declarations go at the top of blocks. Keep `int` and `long` out of hot loops. Always rerun both checks.
- **Character constants:** the `c64` target translates them to PETSCII in **both** cc65 and ca65. Front-end code (C or assembly) must be built with `-t none`, as `build.bat` does. The sim65 tests use `sim6502`, which does not translate, so they cannot catch this; test in VICE too.
